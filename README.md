# BSOD Checker

Настольная утилита для первичной диагностики сбоев Windows: события системного журнала, автоматический разбор дампов, рекомендации и обратимые настройки. Интерфейс на русском языке.

## Установка и запуск

Нужны Windows 10/11, Python 3.10 или новее с Tkinter (входит в официальный установщик Python) и Windows PowerShell 5.1. Скачайте исходный код и в папке проекта выполните:

```powershell
py main.py
```

Для **автоматического анализа содержимого дампов** нужен `cdb.exe` из [Debugging Tools for Windows](https://learn.microsoft.com/windows-hardware/drivers/debugger/debugger-download-tools). Приложение ищет его в PATH и стандартных папках Windows Kits; нестандартный путь можно указать на вкладке «Настройки». Если CDB не найден и есть дамп для анализа, приложение предложит скачать официальный установщик Windows SDK с сайта Microsoft и установить только компонент отладки. Это требует интернета, согласия пользователя и подтверждения UAC с правами администратора; установщик может дополнительно загружать файлы и изменяет системную установку SDK. Перед запуском проверяется действительная цифровая подпись Microsoft. Если загрузка или установка не удалась, доступен ручной выбор пути; при отказе анализ событий продолжится без разбора дампов. Отдельная установка WinDbg из Microsoft Store не гарантирует наличия доступного `cdb.exe`. Python-зависимостей из сторонних пакетов нет.

Нажмите «Запустить анализ» и выберите дамп, событие или текущий снимок системы в списке. Кнопка «Открыть дамп…» позволяет отдельно разобрать выбранный файл, в том числе вне системных папок. При недостаточных правах на чтение журнала или дампов попробуйте запустить программу от имени администратора. При отсутствии отладчика программа покажет предупреждение, список доступных дампов и сведения журнала, но не будет выдавать их за результаты разбора содержимого.

## Анализ и ограничения

При сканировании проверяются `%SystemRoot%\MEMORY.DMP` и `%SystemRoot%\Minidump\*.dmp`, затем `cdb.exe` запускается с командой `!analyze -v` для каждого из наиболее свежих дампов. По умолчанию анализируются до 10 файлов, предел можно изменить на вкладке «Настройки» (1–100). Остальные файлы отображаются с пометкой о пропуске. Время дампа не ограничивается периодом поиска событий. Каждый запуск отладчика ограничен 180 секундами; большие дампы и загрузка символов могут занять время.

Для каждого дампа интерфейс и JSON-отчёт показывают доступные поля: код и название остановки, аргументы, предполагаемую причину, образ, модуль, процесс, идентификатор и хэш сбоя, символ, версию ОС, показатели анализа, стек, предупреждения и полный исходный вывод отладчика. Состав информации зависит от типа и состояния дампа и доступности символов. При ошибке, неполном выводе или истечении времени отображается соответствующий статус. Указанный отладчиком модуль — лишь зацепка, а не доказанная причина сбоя; рекомендации также не заменяют ручную диагностику.

По умолчанию отладчику передаётся только локальный кэш символов `%LOCALAPPDATA%\BSODChecker\symbols`. Для более полного анализа разрешите в настройках загрузку символов с `https://msdl.microsoft.com/download/symbols`. Тогда отладчик подключается к Microsoft, а идентификаторы и названия запрашиваемых файлов могут передаваться серверу. Само приложение не загружает дампы; при отключённой настройке сервер символов в команду не добавляется. Локальный кэш сохраняется между запусками.

Программа также читает события системного журнала: BugCheck (ID 1001, Microsoft-Windows-WER-SystemErrorReporting), Kernel-Power 41, EventLog 6008, WHEA-Logger (1, 17, 18, 19, 47), disk (7, 51, 153), storahci/stornvme/iaStorA/iaStorAVC (129) и volmgr (161, 162). Эти дополнительные события помогают найти аппаратные ошибки, проблемы ввода-вывода и записи дампов, но не доказывают их связь с конкретным BSOD. Также собирается **текущий** снимок свободного места системного тома и доступной оперативной памяти; он не отражает состояние в момент сбоя. Максимум событий ограничивает количество записей с нужными ID **до** фильтрации по источнику. События 41 и 6008 не доказывают наличие BSOD. Не все сбои оставляют события или дампы; отсутствие результатов не гарантирует исправность компьютера.

Кнопка экспорта сохраняет JSON с событиями, путями, результатами разбора, полным выводом отладчика и предупреждениями. Дампы и отчёты могут содержать конфиденциальную информацию — проверяйте их перед передачей другим людям.

## Твики и восстановление

Твики изменяют только параметры реестра текущего пользователя (отображение расширений файлов и прозрачность). Они не применяются автоматически и требуют подтверждения. Перед первым применением исходное значение сохраняется в `%LOCALAPPDATA%\BSODChecker\tweaks-backup.json`; повторное применение не перезаписывает резервную копию. Кнопка «Восстановить» возвращает значение или удаляет его, если оно отсутствовало. Восстановление может перезаписать последующие ручные изменения этого параметра. Не удаляйте файл резервной копии до восстановления. Для вступления изменений в силу может потребоваться перезапуск Проводника или выход из системы. Прирост производительности не гарантируется.

Настройки хранятся в `%LOCALAPPDATA%\BSODChecker\settings.json`. Перед настройкой системы рекомендуется создать точку восстановления.

## Тесты

```powershell
py -m unittest discover -s tests -v
```

Тесты имитируют загрузку и установку, отладчик и реестр, не изменяя реальные настройки Windows. Для проверки полноценного анализа запустите приложение в Windows с установленным `cdb.exe` и настоящим дампом ядра.
